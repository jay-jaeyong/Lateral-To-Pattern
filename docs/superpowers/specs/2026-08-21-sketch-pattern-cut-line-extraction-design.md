# 스케치 패턴 재단선 추출 v3 설계

- 날짜: 2026-08-21
- 상태: 승인됨
- 대상: `Shoe-Image-To-Pattern` Step 3 `line_art_conversion`
- 근거 문서: `docs/source_of_truth.md`, `CONTEXT.md`
- 후속 소비자: Pattern-Parser 타일 기반 4-view grouping

## 배경

Step 3는 컬러 패턴을 보기 좋은 선화로 다시 디자인하는 단계가 아니다. 컬러 패턴에서 직접 식별되는 재단선과 그 연결 관계만 보존하고 재봉선, 메시 조직, 무늬, 색상과 재질 표현을 제거하는 변환이다.

v2에서는 넓은 비백색 영역을 비우고 모든 선을 다시 그리는 래스터 후처리를 적용했다. 이 방식은 서로 맞닿은 비백색 영역의 내부 경계를 제거했고, 실제 재단선 주변에 거친 점과 5×5 검은 점을 만들었으며, 생성 단계에서 빠진 메시 경계를 복구하지도 못했다. 따라서 v3는 생성 결과를 픽셀 그대로 저장하고, 필요한 정확도는 요청 설정과 Step 3 프롬프트에서 확보한다.

## 결정 요약

1. 기존 컬러 패턴은 재생성하지 않는다.
2. Step 2의 기본 이미지 설정 `4K / 2:3`은 유지한다.
3. Step 3는 `4K`만 지정하고 `aspect_ratio`를 생략하여 입력 컬러 패턴의 화면 비율을 따르게 한다.
4. Step 3는 픽셀 크기의 완전 동일성보다 프레이밍, 정규화 좌표, 곡률, 배치 및 연결 관계 보존을 우선한다.
5. 이진화, 임계값 처리, 침식·팽창·골격화, 선 재그리기, 채움 제거, 티끌 제거, 안티앨리어싱 추가 및 출력 리사이즈를 모두 제거한다.
6. 후처리가 없으므로 원시본을 별도로 저장하지 않는다. 생성 응답이 곧 최종본이다.
7. v3 결과는 `images/new_patterns/v3/`에 저장하여 v2와 기존 결과를 보존한다.
8. 시각 품질 게이트와 이미지 내용에 따른 자동 재생성은 추가하지 않는다. 기존 API 전송 오류 재시도는 그대로 둔다.
9. 에이전트는 생성 이미지의 내용이나 시각 품질을 검토하지 않는다. 사람만 결과를 검토한다.

## 목표

1. 컬러 패턴에서 식별되는 재단선만 남긴다.
2. 입력의 화면 비율, 프레이밍과 부품 배치를 유지한다.
3. 재단선의 정규화 좌표, 곡률과 관찰된 접속 구조를 유지한다.
4. 메시 패턴 파트의 재단 경계를 닫힌 순환 경계로 보존한다.
5. 순백 배경 위에 검은 재단선을 생성하고 유채색, 회색 채움, 음영과 재질 표현을 남기지 않는다.
6. 기존 `_color` 이미지 12개를 입력으로 v3 스케치 12개를 생성할 수 있게 한다.
7. Pattern-Parser가 컬러·스케치 이미지를 등록한 뒤 같은 파트가 포함된 타일끼리 묶을 수 있게 한다.

## 비목표

- 컬러 패턴 재생성
- 가려졌거나 식별되지 않는 재단선 추론 또는 복원
- 래스터 후처리로 선 연결, 폐합 또는 잡티 제거
- 강제 출력 리사이즈
- 재봉 마진 계산 또는 추가
- 부품별 레이어나 별도 파일 생성
- 자동 시각 품질 판정, 품질 게이트 또는 이미지 내용에 따른 Gemini 자동 재호출
- 프롬프트만으로 픽셀 단위 99% 일치 보장

## 크기와 등록 전략

### 왜 컬러와 스케치 크기가 달라졌는가

현재 `IMAGE_CONFIG`는 모든 이미지 생성 요청에 `4K / 2:3`을 적용한다. 기존 컬러 패턴들은 생성 시점과 설정이 달라 `3392×5056`, `3244×5248`, `3232×5248`, `2825×3309` 등 여러 크기로 존재한다. Step 3가 입력 크기와 관계없이 고정 `4K / 2:3`을 사용하면서 v2 스케치는 모두 `3392×5056`으로 생성되었다. 저장 로직이 크기를 바꾼 것이 아니라 API 요청 설정이 출력 크기와 비율을 고정한 결과다.

### Step 3 요청 계약

- `image_size="4K"`를 명시한다.
- `aspect_ratio` 필드는 요청에서 생략한다.
- Gemini가 입력 이미지의 화면 비율을 따르도록 한다.
- 임의 비율 문자열이나 입력 픽셀 크기에서 계산한 비지원 비율을 보내지 않는다.
- 출력 후 컬러 입력 크기로 LANCZOS 리사이즈하지 않는다.

“컬러 입력 크기로 LANCZOS 리사이즈”는 생성된 스케치의 가로·세로 픽셀 수를 컬러 이미지와 같게 늘리거나 줄이는 보간 작업이다. 이 작업은 파일 크기만 맞출 뿐 이미 어긋난 재단선 좌표와 형상을 복구하지 못하며, 선 가장자리에 새 회색 픽셀을 만든다. 따라서 v3에서는 사용하지 않는다.

### Pattern-Parser와의 연결

Pattern-Parser 설계는 다음 등록 방식을 사용한다.

- 두 이미지 크기가 같으면 `identity` 등록
- 화면 비율 차이가 1% 이내면 `resize` 등록 후 같은 타일 좌표계 사용
- 화면 비율 차이가 크면 `unregistered`로 처리하고 컬러 타일 생략

따라서 뒤 단계의 정확도에는 “픽셀 크기가 우연히 같음”보다 “같은 재단선이 같은 정규화 위치와 형상에 있음”이 더 중요하다. v3는 입력 화면 비율을 따르게 하여 등록 가능성을 높이고, 프롬프트로 기하 보존을 강제한다.

## 재단선 판정 계약

### 유지

- 패턴 부품의 식별 가능한 외곽 재단선
- 노쏘 재단선
- 고체 패널에 독립된 원형 또는 타원형의 닫힌 펀칭 재단선
- 직접 식별되는 하드웨어 장착용 구멍
- 별도 원단으로 재단한 부품임이 명확한 로고·장식의 외곽 재단선
- 메시 원단이 위치할 패턴 파트의 재단 경계

### 제거

- 재봉선과 실 모양
- 메시 내부의 반복 조직, 니트, 격자, 엠보싱과 원단결
- 인쇄·자수 로고, 글자, 숫자와 표면 무늬
- 금속 장식, 금속 아일릿과 버클의 외형
- 색상 경계, 채움, 광택, 하이라이트, 그림자, 음영과 재질 표현
- 재봉 마진
- 가려졌거나 정체가 불확실한 선

### 메시 패턴 파트 폐합

메시 조직을 제거하기 전에 메시 패턴 파트의 둘레를 하나의 닫힌 순환 경계로 식별한다.

- 파트 고유 경계는 관찰되는 곡선을 그대로 유지한다.
- 경계 끝이 전체 외곽선, 발목 부근 경계 또는 인접 파트 재단선에 닿으면 관찰된 정확한 접점까지 이어야 한다.
- 접점 직전에 선을 끊거나 흰 틈을 만들지 않는다.
- 둘레 일부가 다른 재단선과 공유되면 그 공유 구간을 닫힌 둘레의 일부로 사용한다.
- 공유 구간 옆에 평행한 중복선을 새로 만들지 않는다.
- 실제로 가려져 관찰할 수 없는 구간은 폐합을 위해 추론하지 않는다.

사용자가 빨간 표시로 제시한 다음 v2 결과는 이 규칙의 회귀 근거다.

- `images/new_patterns/v2/asics_GEL-STRATUS_MC_sketch.png`
- `images/new_patterns/v2/필라2_sketch.png`
- `images/new_patterns/v2/필라1_sketch.png`

이 파일들은 프롬프트 요구사항을 정의하는 근거로만 사용한다. 구현 및 검토 에이전트는 v3 생성 결과를 열어 비교하거나 시각 판정하지 않는다.

## 기하 보존 계약

- 입력과 같은 화면 비율, 프레이밍 및 캔버스 범위를 유지한다.
- 각 점의 정규화 좌표 `x / width`, `y / height`를 유지한다.
- 재단선의 곡률, 상대 길이, 부품 간 간격과 배치를 유지한다.
- 확대, 축소, 크롭, 회전, 반전 또는 개별 부품 이동을 하지 않는다.
- 직선화, 대칭화, 곡선 보정 또는 보기 좋은 재배치를 하지 않는다.
- 입력에서 맞닿은 재단선은 같은 관찰 위치에서 맞닿게 한다.
- 전체 외곽 재단선은 닫힌 선으로 유지한다.
- 내부 재단선은 닫힌 루프이거나 다른 식별된 재단선에 닿아 끝나야 한다.
- 입력에 없는 선이나 가려진 구간을 새로 만들지 않는다.

픽셀 단위 99% 일치는 품질 목표로 유지하지만 자동 수용 기준으로 사용하지 않는다. 생성 모델은 래스터 복사기가 아니므로 동일 픽셀 크기와 픽셀별 일치를 보장하지 않는다.

## 렌더링 계약

- 배경은 순백이다.
- 재단선 중심은 순검정의 선명한 실선이다.
- 검은 선 가장자리에 생성 모델이 만든 중립 회색 안티앨리어싱 픽셀은 허용한다.
- 유채색 픽셀, 회색 채움, 음영, 그림자, 재질 표현과 반투명 장식은 금지한다.
- 점선, 의미별 색상 구분과 설명 라벨은 사용하지 않는다.
- 출력은 한 장의 평면 이미지다.

후처리에서 안티앨리어싱을 만들거나 제거하지 않는다. 생성 모델이 반환한 픽셀을 그대로 저장한다.

## 코드 설계

### `config/gemini_config.py`

기존 `IMAGE_CONFIG(4K / 2:3)`는 Step 1·2 및 기본 채팅 설정을 위해 유지한다. 입력 비율 추종용 설정을 추가하고 `build_response_config`에 호출별 선택 인자를 둔다.

```python
INPUT_ASPECT_IMAGE_CONFIG = types.ImageConfig(image_size="4K")


def build_response_config(
    modalities: list[str] | None,
    response_schema=None,
    match_input_aspect_ratio: bool = False,
) -> types.GenerateContentConfig | None:
    if not modalities and not match_input_aspect_ratio:
        return None

    effective_modalities = list(modalities or RESPONSE_MODALITIES)
    kwargs = {
        "response_modalities": effective_modalities,
        "safety_settings": SAFETY_SETTINGS,
        "temperature": 0,
    }
    if "IMAGE" in effective_modalities:
        kwargs["image_config"] = (
            INPUT_ASPECT_IMAGE_CONFIG
            if match_input_aspect_ratio
            else IMAGE_CONFIG
        )
    if response_schema is not None:
        kwargs["response_mime_type"] = "application/json"
        kwargs["response_schema"] = response_schema

    return types.GenerateContentConfig(**kwargs)
```

이 인터페이스는 기존 호출의 기본 동작을 보존하면서 Step 3만 명시적으로 입력 비율 추종 설정을 받게 한다.

### `config/prompts.py`

Step 3에 다음 메타데이터를 둔다.

```python
"match_input_aspect_ratio": True,
```

`postprocess_sketch` 플래그는 제거한다. `enabled=False`, `fresh_session=True`, `include_prev_texts=False`는 유지한다.

프롬프트는 픽셀 크기 완전 동일 대신 화면 비율, 프레이밍, 정규화 좌표와 재단선 접속 구조 보존을 지시한다. 메시 경계 폐합과 공유 재단선 규칙을 명시한다.

### `core/pipeline.py`

- `utils.sketch_postprocessor` import를 제거한다.
- `build_response_config` 호출에 `match_input_aspect_ratio=config.get("match_input_aspect_ratio", False)`를 전달한다.
- Step 3 응답 직후의 후처리 분기를 삭제한다.
- `StepResponse.images`를 수정하지 않고 저장 및 다음 결과 객체로 전달한다.

### `scripts/run_step3_on_color_patterns.py`

- 출력 디렉터리를 `images/new_patterns/v3/`로 바꾼다.
- Step 3 전체 설정에서 프롬프트와 `match_input_aspect_ratio` 값을 읽는다.
- `client.send`에 Step 3용 응답 설정을 전달한다.
- 반환 이미지에 후처리나 리사이즈를 적용하지 않고 직접 저장한다.
- 기존 파일 건너뛰기 동작은 유지한다.

### 삭제

- `utils/sketch_postprocessor.py`
- `tests/test_sketch_postprocessor.py`

## 검증 경계

자동 검증은 다음에 한정한다.

- 단위 및 회귀 테스트 통과
- Step 3 호출 설정에 `4K`가 있고 `aspect_ratio`가 없는지 확인
- Step 2 기본 설정이 계속 `4K / 2:3`인지 확인
- 생성 명령 종료 상태
- `images/new_patterns/v3/`에 기대한 이름의 스케치 파일 12개가 존재하는지 확인
- 파일 형식과 픽셀 크기 같은 비시각 메타데이터 확인

다음 작업은 하지 않는다.

- 생성 이미지 열기
- 확대, 오버레이 또는 스크린샷 비교
- 재단선 폐합, 색상 잔존, 점 또는 선 품질의 에이전트 판정
- 실패로 간주하여 자동 재생성

기존 `GeminiClient`의 API 전송 실패 재시도는 시각 품질 재생성이 아니므로 이 설계에서 변경하지 않는다.

시각 수용 여부는 사용자가 직접 판단한다.

## 수용 기준

- 기존 `_color` 파일은 변경되거나 재생성되지 않는다.
- Step 2 기본 설정은 `4K / 2:3`을 유지한다.
- Step 3 요청은 `4K`이며 `aspect_ratio`를 명시하지 않는다.
- Step 3 프롬프트가 정규화 좌표, 프레이밍, 곡률, 배치 및 관찰된 접속 구조 보존을 요구한다.
- 메시 패턴 파트의 닫힌 순환 경계, 정확한 접점 및 공유 재단선 규칙이 명시되어 있다.
- 원형과 타원형 펀칭이 모두 유지 대상이다.
- 모든 래스터 후처리와 강제 리사이즈가 제거된다.
- 생성 응답과 최종 저장본 사이에 픽셀 변환이 없다.
- 별도 원시본이 생성되지 않는다.
- Step 3의 비활성화 및 세션 격리 설정은 유지된다.
- 결과 경로는 `images/new_patterns/v3/`다.
- 실행 시 12개 입력에 대응하는 12개 결과가 생성된다.
- 자동 시각 품질 게이트, 에이전트 이미지 검토 및 자동 재생성이 없다.

## 위험과 대응

### 모델이 입력 크기와 정확히 같은 픽셀 크기를 반환하지 않음

허용한다. 화면 비율이 유지되면 Pattern-Parser 등록 단계가 크기를 맞춘다. 강제 후처리 리사이즈보다 재단선의 정규화 위치 보존을 우선한다.

### 모델이 메시 경계를 누락하거나 색을 남김

프롬프트 계약을 강화하지만 자동 수정하지 않는다. 후처리는 공유 경계를 파괴하거나 새 결함을 만들 수 있으므로 적용하지 않는다. 사람의 검토 결과를 다음 프롬프트 개선 근거로 사용한다.

### 생성 모델이 99% 픽셀 일치를 안정적으로 달성하지 못함

이 변경에서 결정론적 CV 추출기를 새로 만들지 않는다. 품질 목표가 계속 충족되지 않으면 별도 설계로 생성형 변환을 대체할지 검토한다.
