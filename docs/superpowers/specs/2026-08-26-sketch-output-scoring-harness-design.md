# 스케치 패턴 출력 채점 하네스 설계

- 날짜: 2026-08-26
- 상태: 승인됨
- 대상: `Shoe-Image-To-Pattern` Step 3 출력 진단과 프롬프트 판본 비교
- 근거 문서: `docs/source_of_truth.md`, `CONTEXT.md`, `docs/superpowers/specs/2026-08-21-sketch-pattern-cut-line-extraction-design.md`
- 후속 소비자: Step 3 프롬프트 회귀 분석 및 사람의 시각 판정

## 배경

Step 3 프롬프트를 여러 차례 수정했지만 생성 결과에는 서로 다른 실패가 반복됐다. `images/output-5/nike_p6000_sketch.png`는 컬러 패턴의 전체 틀과 toe cap, logo, heel, quarter 측포 형상이 달라졌고, 사용자가 빨간 바운딩박스를 그린 `images/output-5/푸마2_sketch.jpeg`와 `images/output-5/필라1_sketch.jpeg`에는 이어져야 하는 동일 재단선의 단절이 남았다.

지금까지의 비교는 판본당 한 장을 사람이 눈으로 보고 설명하는 방식이었다. 이 방식은 화면비 붕괴, 전체 틀 변화, 면 채움, 유채색 잔존과 흐린 획처럼 계산 가능한 회귀와, 특정 재단선의 연결·형상처럼 사람의 의미 주석이 필요한 회귀를 같은 기준으로 반복 측정하지 못한다. 또한 이전 생성물 자체를 정답으로 삼으면 기존 누락과 할루시네이션을 다음 판본의 기준으로 굳힐 위험이 있다.

따라서 프롬프트를 더 수정하기 전에 기존 컬러 패턴과 스케치 출력을 읽기 전용으로 채점하는 진단 하네스를 만든다. 하네스는 생성 파이프라인과 분리하며 이미지 파일을 수정하거나 결과 수용·재생성을 자동으로 결정하지 않는다.

## 결정 요약

1. 하네스는 진단 전용이다. 생성, 저장, 품질 게이트와 자동 재생성 경로에 연결하지 않는다.
2. 컬러 패턴 원본과 사람 주석만 정답 근거로 사용한다. 기존 스케치는 프롬프트 판본 간 비교 대상이지 정답이 아니다.
3. 모든 비교는 정규화 좌표를 사용한다. 자동 이동, 회전, 반전, 원근 보정, 워핑과 탄성 정렬을 하지 않는다.
4. 자동 지표는 결정론적으로 계산하고 외부 API, AI 판정과 이미지 임베딩을 사용하지 않는다.
5. 의미가 필요한 회귀는 사람 주석으로 보완한다. 연결 오류는 바운딩박스와 동일 재단선 양쪽 앵커, 형상 오류는 바운딩박스와 기대 경계 폴리라인을 사용한다.
6. medial과 lateral은 대칭이라고 가정하지 않는다. 반대쪽 면의 형상 유사도, 좌우 반전 비교와 대칭 점수는 만들지 않는다.
7. 주석 좌표는 사용자가 숫자로 입력하지 않는다. Flask와 HTML canvas로 만든 로컬 웹페이지에서 드래그와 클릭으로 작성한다.
8. 빨간 바운딩박스가 합성된 이미지는 초기 박스 위치를 가져오는 자료로만 사용한다. 깨끗한 대응 출력이 없으면 픽셀 지표는 `not_scored`로 남긴다.
9. 지표는 단일 총점으로 합치지 않는다. 지표별 수치, 신뢰도와 `pass`, `warn`, `fail`, `not_scored` 상태를 제공한다.
10. 명확한 불변식만 처음부터 판정한다. 형상·경계 일치 지표는 사람이 승인한 정상 사례가 생길 때까지 수치와 신뢰도만 기록한다.
11. 상세 결과는 JSON, 판본 비교 요약은 CSV로 저장한다. 보고서는 실행별로 보존하고 이전 실행을 덮어쓰지 않는다.
12. 이미지, 중간 마스크와 오버레이 이미지는 저장하지 않는다. 주석·채점 오버레이는 웹페이지 canvas에서만 표시한다.
13. 정식 의존성으로 `Flask`, `numpy`, `opencv-python-headless`를 추가한다. Streamlit, SciPy, scikit-image와 프런트엔드 프레임워크는 추가하지 않는다.

## 목표

1. 기존 `images/output-*` 결과를 같은 규칙으로 반복 채점한다.
2. 화면비, 방향, 전체 틀, 유채색, 면 채움과 흐린 획 회귀를 수치로 기록한다.
3. 사람이 지정한 동일 재단선의 단절을 앵커 간 연결성과 최대 단절 길이로 측정한다.
4. 사람이 지정한 toe cap, logo, heel, quarter 등 필수 경계의 검출률과 위치 오차를 측정한다.
5. 모든 정상 경계가 주석된 영역에서는 누락 선과 추가 선 비율을 함께 측정한다.
6. 자동 측정이 신뢰할 수 없는 입력은 억지로 점수를 만들지 않고 `not_scored`와 사유를 남긴다.
7. 프롬프트 판본별 지표 중앙값과 개선·동일·악화 이미지 수를 비교한다.
8. 컬러 원본, 스케치 출력과 빨간 표시 이미지를 수정하지 않는다.

## 비목표

- 생성 결과의 자동 합격·불합격에 따른 저장 또는 삭제
- Gemini 자동 재호출이나 품질 기반 재시도
- 스케치 이미지의 이진화, 임계값 처리, 침식·팽창, 선 연결, 채움 제거 또는 리사이즈
- 생성 파이프라인에 검사 게이트 추가
- AI 모델을 이용한 부품 의미 판정
- medial·lateral 대칭 또는 형상 유사도 판정
- 이전 스케치 출력을 정답 이미지로 사용
- 전체 신발 패턴의 완전한 수동 벡터화
- 첫 버전에서 판본 비교 대시보드 구현
- 표시가 합성된 오버레이 이미지 파일 저장

## 기준 데이터 전략

### Dataset manifest

파일명은 초기 후보 탐색에만 사용하고 실제 채점은 확정된 manifest를 따른다.

```json
{
  "schema_version": 1,
  "items": {
    "nike_p6000": {
      "source": "images/nike_p6000.jpeg",
      "expected_canvas_ratio": "2:3",
      "outputs": {
        "output-5": "images/output-5/nike_p6000_sketch.png"
      }
    },
    "푸마2": {
      "source": "images/푸마2_color.png",
      "expected_canvas_ratio": "2:3",
      "outputs": {
        "output-5-annotated": "images/output-5/푸마2_sketch.jpeg"
      }
    }
  }
}
```

- `_color`와 `_sketch` 접미사로 manifest 후보를 자동 생성한다.
- `nike_p6000.jpeg`처럼 이름이 불규칙하거나 후보가 여러 개인 항목은 웹페이지에서 한 번 확인한다.
- 새 `output-N` 디렉터리가 생기면 기존 항목의 `outputs` 후보로 추가한다.
- 실제 파일 경로, 확장자와 Unicode 정규화 차이는 manifest에 기록된 경로를 권위로 삼는다.
- manifest 밖의 파일을 채점하지 않는다.

### 정답 근거

- 컬러 패턴 원본은 캔버스, 전체 틀, 부품 배치와 기대 재단선 주석의 기준이다.
- 사람 주석은 어떤 경계가 재단선인지, 어느 두 끝이 이어져야 하는지의 기준이다.
- 기존 스케치는 판본 비교 대상으로만 사용한다.
- 사람이 승인한 정상 스케치 2~3개가 생기기 전에는 실루엣·경계 일치 지표의 `pass`, `warn`, `fail` 문턱을 확정하지 않는다.

## 주석 모델

모든 좌표는 `[0, 1]` 범위의 정규화 좌표로 저장한다. 이미지 크기가 달라도 같은 위치에 적용할 수 있으며 숫자 좌표는 웹페이지가 자동으로 계산한다.

### 연결 주석

푸마2와 필라1처럼 동일 재단선이 박스 안에서 끊긴 회귀에 사용한다.

```json
{
  "id": "quarter-seam-1",
  "type": "connection",
  "target_box": [0.31, 0.42, 0.39, 0.49],
  "anchors": {
    "start_region": [0.32, 0.45, 0.33, 0.47],
    "end_region": [0.37, 0.44, 0.38, 0.46]
  }
}
```

- 앵커는 반대쪽 면이 아니라 끊긴 동일 재단선의 양쪽 끝을 담는 작은 영역이다.
- 하네스는 두 앵커를 지나는 잉크가 같은 연결 성분인지 검사한다.
- medial·lateral 비교, 좌우 반전과 상대 면 유사도는 사용하지 않는다.
- 빨간 박스 안에서 선 끝 후보가 정확히 두 개면 자동 제안한다.
- 후보가 없거나 세 개 이상이면 사용자가 두 끝을 순서대로 클릭한다.

### 필수 경계 주석

Nike P6000의 toe cap, logo, heel, quarter처럼 특정 경계가 반드시 존재해야 하는 영역에 사용한다.

```json
{
  "id": "toe-cap-boundary",
  "type": "required_path",
  "label": "toe_cap",
  "target_box": [0.11, 0.68, 0.29, 0.82],
  "paths": [
    [[0.12, 0.74], [0.16, 0.72], [0.22, 0.73], [0.28, 0.78]]
  ]
}
```

- 사용자는 컬러 원본 위에서 재단선인 경계를 클릭해 짧은 폴리라인으로 표시한다.
- 하네스는 출력 선의 검출률과 기대 경계까지의 위치 오차를 계산한다.
- 박스 안의 주석되지 않은 다른 선은 오류로 판정하지 않는다.

### 완전 영역 주석

박스 안의 모든 정상 재단선을 사람이 표시한 경우에만 사용한다.

```json
{
  "id": "heel-complete",
  "type": "complete_roi",
  "label": "heel",
  "target_box": [0.65, 0.08, 0.88, 0.25],
  "paths": [
    [[0.67, 0.20], [0.73, 0.16], [0.82, 0.15]],
    [[0.70, 0.23], [0.76, 0.21], [0.85, 0.22]]
  ]
}
```

- 기대 경계 누락률과 주석되지 않은 추가 선 비율을 모두 계산한다.
- 기본 주석 유형은 `required_path`이며, 추가 선 회귀를 측정해야 할 때만 `complete_roi`를 사용한다.

### 빨간 표시 이미지 가져오기

- 빨간 픽셀의 색상 범위와 연결 성분을 사용해 사각형 후보를 찾는다.
- 검출된 박스를 웹페이지에서 사용자에게 보여주고 저장 전에 확인받는다.
- 빨간 픽셀은 채점 마스크에서 제거하거나 복원하지 않는다.
- 깨끗한 대응 출력이 없으면 해당 출력의 픽셀 지표는 `not_scored`로 기록한다.
- 가져온 정규화 박스와 앵커는 다음 깨끗한 출력에 재사용한다.

## 좌표와 등록 전략

- 원본 좌표는 `x / source_width`, `y / source_height`로 정규화한다.
- 출력 좌표는 `x / output_width`, `y / output_height`로 정규화한다.
- 비교 계산을 위해서만 메모리에서 공통 크기의 정규화 캔버스로 축소한다.
- 자동 평행 이동, 회전, 반전, 원근 보정, 비선형 워핑과 탄성 정렬을 하지 않는다.
- 전체 패턴이나 부품이 움직인 오류는 정렬로 숨기지 않고 그대로 점수에 반영한다.
- 축소 이미지, 마스크, 거리 변환과 오버레이는 디스크에 저장하지 않는다.

## 자동 측정 계약

### 화면비와 방향

- manifest의 `expected_canvas_ratio`와 출력의 화면비 편차를 계산한다.
- 기대 방향과 실제 방향이 다르면 `fail`이다.
- 초기 기본값은 화면비 상대 편차 `2% 이하 pass`, `2% 초과 5% 이하 warn`, `5% 초과 fail`로 두고 설정 파일에서 변경할 수 있게 한다.

### 실루엣 IoU

- 이미지 테두리에서 배경색을 추정하고 전경 마스크를 만든다.
- 컬러 패턴과 스케치를 정규화 캔버스에 축소한 뒤 IoU를 계산한다.
- 배경과 원단의 색차, 전경 분리 안정성과 최대 연결 성분 지배율로 신뢰도를 계산한다.
- 신뢰도가 문턱보다 낮으면 `not_scored`와 사유를 기록한다.
- 승인된 정상 사례가 생기기 전에는 수치와 신뢰도만 기록한다.

### 유채색 픽셀

- RGB 최대값과 최소값의 차이로 중립색이 아닌 픽셀 비율을 계산한다.
- JPEG 압축 잡음을 고려한 색차 문턱을 설정 파일로 둔다.
- 초기 기본값은 전체 픽셀 대비 `0.05% 이하 pass`, `0.05% 초과 0.2% 이하 warn`, `0.2% 초과 fail`이다.

### 검정 면 채움

- 어두운 픽셀 마스크에서 선 굵기보다 넓은 내부가 존재하는 연결 영역의 비율을 계산한다.
- 닫힌 재단선 내부의 흰색은 채움으로 계산하지 않는다.
- 초기 기본값은 전체 픽셀 대비 넓은 검정 내부 `0.05% 이하 pass`, `0.05% 초과 0.2% 이하 warn`, `0.2% 초과 fail`이다.

### 흐린 획

- 비백색 잉크 후보 중 국소 대비가 낮고 선 중심의 검정도가 부족한 픽셀 비율을 계산한다.
- JPEG 안티앨리어싱과 정상적인 선 가장자리 회색은 제외한다.
- 승인된 정상 사례가 생기기 전에는 수치와 신뢰도만 기록한다.

### 연결 주석

- 두 앵커 영역 안에 잉크가 존재하는지 확인한다.
- 동일 연결 성분이 양쪽 앵커와 만나는지 검사한다.
- 연결되지 않으면 두 성분 사이의 최소 거리와 최대 흰 단절 길이를 기록한다.
- 앵커 중 하나에서 잉크를 신뢰성 있게 찾지 못하면 `not_scored`다.
- 충분한 신뢰도에서 연결되면 `pass`, 연결되지 않으면 `fail`이다.

### 필수 경계 주석

- 기대 폴리라인 주변의 허용 거리 띠 안에서 출력 잉크 검출률을 계산한다.
- 출력 잉크에서 기대 경계까지의 중앙값·95백분위 위치 오차를 기록한다.
- 승인된 정상 사례가 생기기 전에는 수치와 신뢰도만 기록한다.

### 완전 영역 주석

- `required_path` 지표에 더해 주석된 전체 경계 띠 밖의 출력 잉크 비율을 추가 선 비율로 계산한다.
- 정상적인 다른 경계를 추가 선으로 오판하지 않도록 박스 안의 모든 정상 재단선이 주석된 경우에만 사용한다.
- 승인된 정상 사례가 생기기 전에는 수치와 신뢰도만 기록한다.

## 신뢰도와 상태 계약

모든 지표 결과는 같은 구조를 사용한다.

```json
{
  "score": null,
  "status": "not_scored",
  "confidence": 0.31,
  "reason": "원단과 배경의 색차가 분리 기준보다 작음"
}
```

- `score`는 수치 또는 불리언이며 측정하지 못하면 `null`이다.
- `status`는 `pass`, `warn`, `fail`, `not_scored` 중 하나다.
- `confidence`는 `[0, 1]` 범위다.
- `not_scored`에는 사람이 이해할 수 있는 `reason`이 반드시 있다.
- 신뢰도가 낮은 값을 임의로 `fail`로 바꾸지 않는다.
- 단일 총점과 임의 가중 평균을 만들지 않는다.

## 판본 비교 계약

판본별 비교는 지표마다 별도로 집계한다.

- 지표별 중앙값
- 이전 판본보다 개선, 동일, 악화된 이미지 수
- 연결·필수 경계·완전 영역 주석의 통과·실패·미채점 수
- `not_scored` 개수와 사유 분포
- 입력이 없는 판본이나 출력이 없는 항목은 결측으로 유지

단일 순위나 종합 점수를 만들지 않는다.

## 로컬 주석 웹페이지

### 기술 선택

- Flask는 이미지 목록, manifest, 주석 JSON과 채점 API만 담당한다.
- 기본 HTML canvas와 소량의 JavaScript가 바운딩박스, 앵커, 폴리라인, 확대와 이동을 담당한다.
- Streamlit과 별도 canvas 컴포넌트는 사용하지 않는다.
- 서버는 기본적으로 `127.0.0.1`에만 바인딩하고 외부 공개 기능과 인증을 구현하지 않는다.
- manifest 밖의 파일 경로는 제공하지 않으며 경로 탐색을 거부한다.

### 최소 기능

- dataset 항목과 출력 판본 선택
- 컬러 원본 또는 스케치 표시 전환
- 바운딩박스 생성, 이동, 크기 조절과 삭제
- 동일 재단선의 시작·끝 앵커 클릭
- `required_path`와 `complete_roi` 폴리라인 작성·수정·삭제
- 빨간 박스 이미지에서 박스 후보 자동 가져오기와 사용자 확인
- 정규화 좌표의 sidecar JSON 저장과 다시 불러오기
- 선택한 이미지의 지표와 주석별 채점 결과 표시
- 확대, 축소와 이동

첫 버전에는 판본 전체 대시보드, 사용자 계정, 동시 편집과 원격 저장을 넣지 않는다.

### 오버레이

- 파란 박스: 사람이 지정한 검사 영역
- 초록 앵커: 연결됨
- 빨간 앵커: 연결되지 않음
- 주황 경로: 누락 또는 추가 선
- 회색 표시: 낮은 신뢰도로 `not_scored`

오버레이는 canvas에서만 그리며 이미지 파일로 저장하지 않는다.

## 파일과 모듈 설계

```text
sketch_scoring/
  __init__.py
  manifest.py          # 파일 후보 탐색, manifest 검증과 안전한 경로 해석
  annotations.py       # 주석 스키마, 정규화 좌표와 빨간 박스 가져오기
  metrics.py           # 결정론적 전체 이미지·주석 지표
  reporting.py         # JSON 상세 결과와 CSV 판본 요약
scripts/
  score_sketch_outputs.py
  annotate_sketches.py
templates/
  annotate.html        # CSS와 JavaScript를 포함한 단일 페이지
annotations/sketch-scoring/
  dataset.json
  items/*.json
reports/sketch-scoring/
  <run-id>/results.json
  <run-id>/summary.csv
  latest.json
```

- `latest.json`은 최신 실행 디렉터리와 결과 경로를 가리키는 작은 포인터다.
- 각 실행은 시간과 사용자 지정 라벨을 포함한 별도 디렉터리에 저장하며 이전 결과를 덮어쓰지 않는다.
- 이미지 파일과 중간 계산 산출물은 reports 아래에 복사하지 않는다.

- 개별 지표 실패 때문에 프로세스가 실패 종료하지 않는다.
- manifest·주석 스키마 오류, 파일 읽기 실패와 보고서 저장 실패는 비정상 종료한다.


Pillow는 기존 의존성을 사용한다. SciPy, scikit-image, Streamlit, 외부 AI SDK와 프런트엔드 패키지는 추가하지 않는다.

## 비수정 보장

하네스가 쓸 수 있는 경로는 다음뿐이다.

- `annotations/sketch-scoring/`
- `reports/sketch-scoring/`

다음 경로는 읽기 전용이다.

- `images/`
- `images/output-*/`

채점기는 이미지에 `save`, `write`, `imwrite`를 호출하지 않는다. 마스크, 축소 이미지, 거리 변환과 오버레이는 메모리에서만 존재한다. 웹 API는 manifest 밖의 경로와 이미지 대상 쓰기 요청을 거부한다.

## 테스트 전략

실제 생성 API를 호출하지 않고 작은 합성 이미지와 임시 디렉터리로 검증한다.

### Manifest

- `_color`·`_sketch` 후보 자동 연결
- 불규칙 이름의 `needs_review`
- Unicode NFC/NFD 파일 경로 처리
- 기존 사용자 확정 연결 보존
- manifest 밖 경로 거부

### 주석

- 정규화 좌표 범위 검증
- connection의 두 앵커 필수
- required_path와 complete_roi의 폴리라인 검증
- medial·lateral 비교 필드 거부
- 빨간 사각형 후보 검출
- 모호한 끝점 후보의 사용자 확인 요구
- 깨끗한 출력 부재 시 `not_scored`

### 지표

- 화면비·방향 pass, warn, fail
- 낮은 실루엣 분리 신뢰도의 `not_scored`
- 유채색 픽셀 검출
- 가는 검은 선과 넓은 검정 면 구분
- 안티앨리어싱 가장자리와 흐린 획 구분
- 동일 연결 성분의 앵커 연결 통과
- 끊긴 선의 실패와 단절 길이
- required_path 검출률·위치 오차
- complete_roi 누락·추가 선 비율
- 자동 정렬·워핑을 수행하지 않는 회귀 테스트

### 보고서

- JSON에 수치·상태·신뢰도·사유 포함

- 단일 총점 부재
- 실행별 디렉터리 보존과 `latest.json` 갱신
- 이미지와 중간 마스크 미저장

### Flask

- dataset·이미지·주석 읽기 API

- 개별 이미지 채점 결과 반환

## 검증 경계

자동 검증은 다음을 수행한다.

- 단위 및 회귀 테스트 통과
- 합성 fixture의 지표 기대값 확인
- 임시 이미지의 수정 시간과 해시가 채점 전후 동일한지 확인
- CLI manifest·score 명령 종료 상태
- Flask API 테스트 클라이언트의 주석 저장·재로드
- 결과 JSON·CSV 스키마와 실행 이력 보존 확인

다음 작업은 하지 않는다.

- 생성 이미지 수정
- 품질 점수에 따른 출력 삭제나 Gemini 재호출
- 자동 대칭 판정
- AI 기반 의미 판정
- 사람이 승인하지 않은 형상 지표 문턱 확정

## 수용 기준

- 하네스는 생성 파이프라인에서 import되거나 호출되지 않는다.
- 이미지 파일은 채점과 주석 작성 전후 해시와 수정 시간이 동일하다.
- manifest가 컬러 원본과 여러 출력 판본을 명시적으로 연결한다.
- 모든 주석 좌표가 정규화 좌표로 저장된다.
- 사용자는 숫자 좌표를 직접 입력하지 않고 웹페이지에서 박스·앵커·폴리라인을 작성할 수 있다.
- medial·lateral 대칭, 반전 비교와 반대쪽 형상 유사도 지표가 없다.
- 빨간 표시 이미지는 주석 가져오기 전용이며 깨끗한 출력이 없으면 픽셀 지표가 `not_scored`다.
- 첫 버전은 화면비, 방향, 실루엣, 유채색, 검정 면 채움, 흐린 획, 연결, 필수 경계와 완전 영역 지표를 제공한다.
- 각 지표는 수치, 상태, 신뢰도와 필요 시 `not_scored` 사유를 포함한다.
- 단일 총점이 없다.
- JSON 상세 결과와 CSV 판본 요약만 저장하고 이미지·마스크·오버레이 파일을 저장하지 않는다.
- 보고서는 실행별로 보존되며 이전 실행을 덮어쓰지 않는다.
- Flask 웹페이지는 로컬 전용이고 manifest 밖 파일을 제공하거나 수정하지 않는다.
- `Flask`, `numpy`, `opencv-python-headless`만 새 직접 의존성으로 추가한다.
- 전체 테스트가 통과하며 Gemini API를 호출하지 않는다.

## 위험과 대응

### 흰 원단과 흰 배경을 분리하지 못함

실루엣 분리 신뢰도를 낮추고 `not_scored`로 기록한다. 낮은 신뢰도를 실패로 바꾸지 않는다. 사람이 승인한 정상 사례가 모일 때까지 실루엣 문턱을 확정하지 않는다.

### JPEG 압축 픽셀이 유채색·흐린 획으로 검출됨

색차와 국소 대비 문턱을 설정 파일로 분리하고 합성 JPEG fixture로 보정한다. 정상적인 선 가장자리 안티앨리어싱은 중심선 실패와 구분한다.

### 빨간 박스가 원래 재단선을 가림

빨간 픽셀 아래를 복원하지 않는다. 박스 좌표만 가져오고 깨끗한 출력이 없으면 픽셀 지표를 `not_scored`로 남긴다.

### 앵커 자동 검출이 다른 선 끝을 선택함

자동 후보는 저장 전 제안으로만 표시한다. 후보가 정확히 두 개가 아니거나 사용자가 거부하면 두 앵커를 직접 클릭한다.

### 바운딩박스 안에 정상적인 다른 선이 존재함

기본 `required_path`는 표시한 경계의 존재만 측정한다. 박스 안의 모든 정상 경계를 표시한 `complete_roi`에서만 추가 선 비율을 계산한다.

### 하네스 점수가 새 품질 게이트로 오용됨

생성 코드에서 하네스 패키지를 import하지 않는 테스트를 둔다. CLI 문서와 결과 스키마에 `diagnostic_only`를 기록하고 결과 상태가 저장·삭제·재생성 동작을 유발하지 않게 한다.
